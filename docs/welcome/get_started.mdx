You need Docker with Compose 2.23.1 or later and free local ports `6432` and `7432`. The example includes PostgreSQL, the SPQR router, and the `psql` client. If you already have an empty SPQR cluster, [load the demo there](/welcome/demo_database).

## Start the local demo

Run these commands from a terminal. The loader starts the cluster, creates the messenger tables and routing rules, and loads 100,000 messages. At the end it prints a message count for each shard.

```bash
mkdir spqr-demo && cd spqr-demo &&
curl -fLO https://raw.githubusercontent.com/pg-sharding/spqr/master/examples/messenger/compose.yaml &&
docker compose run --rm load
```

## Connect to SPQR router

From the same directory, open a SQL session on the router.

```bash
docker compose exec router psql -X
```

```sql
SET __spqr__reply_notice TO true;
SELECT title FROM chats WHERE chat_id = 1;
SELECT title FROM chats WHERE chat_id = 1000;
```

The titles are `Space Daily` and `Football Daily`. Both queries went through the same router connection on port `6432`. The `NOTICE` for each query names the shard that answered it.

## Setting up sharding

The router knows the shard addresses from `compose.yaml`. The loader used the admin console on port `7432` to tell the router which tables share a key and which shard owns each range of keys. Keep your SQL session open and [inspect the rules for the two chats you just queried](/welcome/demo_database#read-the-routing-rules).

## Stop or remove the local demo

Exit `psql` with `\q`. From the demo directory, run `docker compose stop` to pause the cluster. Use `docker compose up -d --wait router` to resume it with the same data.

To delete the local demo, including its data and routing rules, run `docker compose down --volumes`. You can then start fresh with `docker compose run --rm load`.

For other installations, see the [router binaries](https://github.com/pg-sharding/spqr/releases), [source build instructions](https://github.com/pg-sharding/spqr#development), and [deployment guide](/deployment/overview).
