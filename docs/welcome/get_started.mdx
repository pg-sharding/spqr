The local demo includes two PostgreSQL shards, the SPQR router, and the `psql` client. If you already have an empty SPQR cluster, [load the demo there](/welcome/demo_database).

<Accordion title="Installed the router with install.sh?">
  If your router is already running with `examples/init.sql`, skip to the `psql` command below.
  To start it, you need two empty PostgreSQL instances on `localhost:5432` and `localhost:5433` that accept connections as `postgres` without a password.
  Run these commands from the directory containing `spqr-router`. The first downloads the example configuration if your release omitted it.

  ```bash
  test -f examples/quickstart.yaml || curl -fsSL -o examples/quickstart.yaml \
    https://raw.githubusercontent.com/pg-sharding/spqr/master/examples/quickstart.yaml
  ./spqr-router run --config examples/quickstart.yaml
  ```

  If the router reports a socket permission error with an older config, set `unix_socket_dir: .` in `examples/quickstart.yaml` and start the router again.

  Open a second terminal and connect to the running router.

  ```bash
  psql -h localhost -p 6432 -U postgres -d postgres
  ```

  On fresh shards, run these commands in `psql`.

  ```sql
  CREATE TABLE users (id int PRIMARY KEY, name text);
  INSERT INTO users VALUES (1, 'Alice');
  INSERT INTO users VALUES (60000, 'Bob');
  SET __spqr__reply_notice TO true;
  SELECT name FROM users WHERE id = 1;
  SELECT name FROM users WHERE id = 60000;
  ```

  The notices show Alice on `sh1` and Bob on `sh2`. The sample rules place IDs starting at 50000 on `sh2`.
</Accordion>

## Start the local demo

You need Git, Docker with Compose 2.23.1 or later, and four free local ports. SPQR uses `6432` and `7432`. The shards use `5441` and `5442`.

<Accordion title="Port already in use?">
  Choose free local ports and export them in the terminal you'll use for the demo.

  ```bash
  export ROUTER_PORT=16432 ADMIN_PORT=17432 SHARD1_PORT=15441 SHARD2_PORT=15442
  ```
</Accordion>

Clone the repository, which includes the Small dataset. The load command starts the router and both shards, then loads the data.

```bash
git clone https://github.com/pg-sharding/messenger.git
cd messenger
docker compose run --rm load
```

When the loader prints `Messenger demo is loaded` and the row counts for both shards, you're ready to connect.

## Connect to SPQR router

From the same directory, open a SQL session on the router.

```bash
docker compose run --rm psql
```

Turn on routing notices and query two chats at opposite ends of the key space.

```sql
SET __spqr__reply_notice TO true;
SELECT title FROM chats WHERE chat_id = 1;
SELECT title FROM chats WHERE chat_id = 1000;
```

Compare each title with the shard named in its `NOTICE`.

| `chat_id` | `title` | Shard shown in `NOTICE` |
| --- | --- | --- |
| 1 | Space Daily | `sh2@shard2:5432` |
| 1000 | Football Daily | `sh1@shard1:5432` |

You used the same connection for both queries. SPQR read the `chat_id` in each query and sent it to the shard that owns that range.

## Read the routing rules

Stay in the same `psql` session. Switch to the admin console on port `7432`, inspect the rules, and switch back.

```sql
\set router_port :PORT
\connect - - - 7432
SHOW relations WHERE relation_name = 'messages';
SHOW key_ranges WHERE distribution_id = 'ds_chats' ORDER BY lower_bound;
\connect - - - :router_port
SET __spqr__reply_notice TO true;
```

The first result identifies `chat_id` as the sharding key for `messages`. The second shows where each range starts and which shard owns it. Use that map to predict which shard will answer each query below.

```sql
SELECT count(*) FROM messages WHERE chat_id = 500;
SELECT count(*) FROM messages WHERE chat_id = 501;
```

Both counts are 43. Check the notices. Chat 500 is on `sh2` and chat 501 is on `sh1`, where the second range starts.

## Stop or remove the local demo

Exit `psql` with `\q`. Run the command you need from the demo directory.

| Action | Command |
| --- | --- |
| Pause the demo | `docker compose pause` |
| Resume after a pause | `docker compose unpause` |
| Reset the sample data and discard your changes to the demo tables | `docker compose run --rm load` |
| Remove the demo and its data | `docker compose down --volumes` |

The router keeps its routing rules in memory. After a router restart, use the reset command to recreate the rules and reload the sample data.

For other installations, see the [router binaries](https://github.com/pg-sharding/spqr/releases), [source build instructions](https://github.com/pg-sharding/spqr#development), and [deployment guide](/deployment/overview).
