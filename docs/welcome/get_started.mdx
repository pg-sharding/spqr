You need Docker with Compose 2.23.1 or later and free local ports `6432` and `7432`. The example includes PostgreSQL, the SPQR router, and the `psql` client. If you already have an empty SPQR cluster, [load the demo there](/welcome/demo_database).

## Start the local demo

Run these commands from a terminal. The first run pulls Docker images and downloads the dataset (~400 MB total). You will see PostgreSQL logs while the cluster starts and row counts when loading finishes.

```bash
mkdir spqr-demo && cd spqr-demo &&
curl -fLO https://raw.githubusercontent.com/pg-sharding/spqr/master/examples/messenger/compose.yaml &&
docker compose run --rm load
```

## Connect to SPQR router

From the same directory, open a SQL session on the router.

```bash
docker compose exec router psql -X
```

Turn on routing notices and query two chats at opposite ends of the key space.

```sql
SET __spqr__reply_notice TO true;
SELECT title FROM chats WHERE chat_id = 1;
SELECT title FROM chats WHERE chat_id = 1000;
```

Each query returns a `NOTICE` naming the shard that answered it:

```
NOTICE:  send query to shard(s) : sh1
  title
-----------
 Space Daily
(1 row)
```

Chat 1 (`Space Daily`) and chat 1000 (`Football Daily`) land on different shards.

## Read the routing rules

Stay in the same `psql` session. Switch to the admin console on port `7432`, inspect the rules, and switch back.

```sql
\set router_port :PORT
\connect - - - 7432
SHOW relations WHERE relation_name = 'messages';
SHOW key_ranges WHERE distribution_id = 'ds_chats' ORDER BY lower_bound;
\connect - - - :router_port
SET __spqr__reply_notice TO true;
```

The first result identifies `chat_id` as the sharding key for `messages`. The second shows the lower bound of each key range and the shard that owns it. In Small on two shards the bounds are `1` and `501`. Use that map to predict which shard will answer, then check with notices:

```sql
SELECT count(*) FROM messages WHERE chat_id = 500;
SELECT count(*) FROM messages WHERE chat_id = 501;
```

For more queries — joins, cross-shard lookups, and cleanup — continue to the [demo database page](/welcome/demo_database#who-wrote-the-latest-message-in-chat-1).

## Stop or remove the local demo

Exit `psql` with `\q`. From the demo directory, run `docker compose stop` to pause the cluster. Use `docker compose up -d --wait router` to resume it with the same data.

To delete the local demo, including its data and routing rules, run `docker compose down --volumes`. You can then start fresh with `docker compose run --rm load`.

For other installations, see the [router binaries](https://github.com/pg-sharding/spqr/releases), [source build instructions](https://github.com/pg-sharding/spqr#development), and [deployment guide](/deployment/overview).
